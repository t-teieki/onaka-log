## 4. 分かったこと

### 4-1. 形式と内部の整合は、どのモデルも問題ない

60回すべてエラーなし、スキーマと意味上のルールに適合した。kcal と PFC の整合も 176品目中 175品目で ±15% 以内。数値の出し方そのものは安定している。

### 4-2. Haiku は品目を落とすことがある

P002 の納豆（未開封のパック）を、**Haiku low は3回とも品目に入れなかった**（medium も一部の回で欠落）。Sonnet・Opus は毎回入れた。品目が抜けるとその分がまるごと記録されないので、正解がなくても分かる明確な欠点。

### 4-3. Haiku の合計は他より 1〜3割低い

5枚中4枚で、Haiku の平均 kcal は Sonnet・Opus より 10〜30% 低かった。Haiku はご飯を毎回「150g・252kcal」と置く傾向があり、Sonnet・Opus は器の大きさから 180〜220g と見積もっていた。どちらが正しいかは正解がないので分からないが、Sonnet と Opus の差は小さい（多くの写真で 5〜10%）。

### 4-4. 再現性は Sonnet・Opus が目安を満たし、Haiku は境界

3回推定のばらつき（CV）は、Opus 3.5%、Sonnet 6.6%（5枚中4枚が 10% 以内、最大 10.1%）、Haiku 約10%（最大 14%）。Haiku は同じ写真でも品目数が変わる回があった（P003 で 3〜7品目）。

### 4-5. 品目の分け方の細かさがモデルで違う

P003 のサラダを、Sonnet・Haiku は「ローストビーフ入りサラダ」1品にまとめ、Opus はローストビーフ・レタス・チーズ・ぶどう・ドレッシングなど8品目に分けた。細かすぎると確認画面の行が増えて直しにくい。プロンプトに「料理単位で分ける（ソース・ドレッシング・トッピングは料理に含める）」と書くのがよい。

### 4-6. 料理名の判別は大きくは外れないが、細部は揺れる

P004 の和菓子は、どら焼き・薯蕷饅頭・もなか風などモデルや回で名前が揺れた（暗く、断面が見えにくい写真）。kcal は 135〜233 と幅が大きい。確認画面で料理名を直せる UI が要る。

### 4-7. 費用と応答時間

- 1回の費用: Haiku 約0.1円 / Sonnet 約1.9円 / Opus 約4.2円
- 1日3回撮るとして月90回: Haiku 約9円 / **Sonnet 約170円** / Opus 約380円。どれも月1000円（NFR-001）に収まる（自分専用の場合）
- 応答 p50: Haiku 2.9秒 / Sonnet 4.3秒 / Opus 7.4秒。目安の 5秒以内は Sonnet まで

### 4-8. プロンプト 0.2.0 で、品目の分け方と欠落が安定した

4-2・4-5 を受けてプロンプトを改訂し（料理・器単位で分ける、ソース・トッピングは料理に含める、パック食品も入れる、水・お茶は入れない、量に決まった値を当てはめない）、Sonnet 5.5・medium で同じ5枚を3回ずつ再実行した（15回、28.4円）。

| 写真 | 0.1.0 kcal（CV・品目数） | 0.2.0 kcal（CV・品目数） | 変化 |
|---|---|---|---|
| P001 ハンバーグ定食 | 738（1.0%・4） | 750（1.4%・4） | ほぼ同じ |
| P002 鶏もも焼き・納豆 | 733（7.4%・3） | 665（3.9%・3） | 納豆は3回とも入った。ばらつきが半分に |
| P003 ローストビーフサラダ | 615（7.5%・**3〜7**） | 648（**0.4%**・**3**） | サラダが毎回1品目にまとまり、品目数がそろった |
| P004 和菓子とお茶 | 217（10.1%・2） | 213（**18.9%**・1） | お茶が外れた。料理名がどら焼き／もなかで揺れ、kcal が 190〜260 に |
| P005 豚肉の炒め物定食 | 794（6.8%・3） | 763（4.7%・3） | ばらつきが減った |

- 品目の分け方は、全写真で3回とも同じ品目数になった（0.1.0 では P003 が 3〜7品目で揺れた）
- P004 は暗く断面が見えない写真で、何の菓子かの判別が揺れた。プロンプトでは直せない種類のばらつきで、確認画面で料理名を直す前提とする
- 応答 p50 4.2秒、1回約1.9円は 0.1.0 と同じ

## 5. 所見

- **推奨は Sonnet 5.5（effort medium）**。品目の欠落がなく、再現性は目安をほぼ満たし、応答も 5秒以内。費用は Haiku の約20倍だが、自分専用なら月170円程度
- プロンプトは **0.2.0 を採用**する。品目の分け方が安定し、欠落もなくなった
- Haiku は OCR（表示をそのまま読む作業）では十分だったが、写真推定（量を見積もる作業）では品目の欠落とばらつきが目立った
- Opus は最も安定しているが、応答が 7秒台で、費用は Sonnet の約2倍。精度を測れない以上、その差に見合うか判断できない
- 将来ストア公開で利用者が増えたら、費用の見直し（Haiku＋プロンプト改善の再検証など）が要る
