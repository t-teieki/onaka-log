# ADR-0001: 仕様駆動＋テスト駆動で開発する

- ステータス: Accepted
- 日付: 2026-11-11
- 関連: HNS-03, TST-01, TST-03, LLM-03

## 背景

セッションをまたいで Claude Code と開発を進めるため、意図がコードではなくドキュメントとテストに残っている必要がある。また「このテストをパスするまで実装して」という指示で実装を任せられる状態を目指す。

## 決定

1. 仕様（`docs/01_requirements`, `docs/02_design`）→ 契約（`contracts/`）→ テスト → 実装 の順で進める。
2. 契約（JSON Schema / OpenAPI）を唯一の正とする。特に **Claude API の入出力は用途ごとにスキーマを定義し、例（valid / invalid）に対するスキーマ検証テストを必ず用意する**。
3. 実装フェーズではテスト・契約を変更しない。変更が必要なら仕様から戻る。
4. 仕様の要件IDをテストから参照し、トレーサビリティを確保する。

## 理由と影響

- 実装者（人・AI）が変わっても、合格基準がテストとして固定される。
- 先にドキュメント・テストを書く分、初速は落ちる。PoC（`poc/`）はこの規律の対象外とし、速度を優先してよい（ただし結果と得られたスキーマは `contracts/` と `docs/` に還元する）。
