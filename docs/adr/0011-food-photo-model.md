# ADR-0011: 写真からの推定は Sonnet 5.5（effort medium）を使う

- ステータス: Accepted
- 日付: 2026-11-13
- 関連: Q-28, Q-29, POC-32, POC-33, POC-41, POC-43, NFR-001, [PoC-3 結果](../../poc/reports/poc3-food-photo.md)

## 背景

PoC-3 で、料理写真5枚（すべて複数品）を Haiku 5.5（low / medium）・Sonnet 5.5（medium）・Opus 5.5（medium）でそれぞれ3回推定した。正解データは用意せず（本番でも正解はなく推定値をそのまま登録する、Q-28）、形式・kcal と PFC の整合・3回推定のばらつき・モデル間の差・品目の分け方で比べた。

| モデル | 品目の欠落 | ばらつき（CV 平均 / 最大） | 応答 p50 | 1回の費用 |
|---|---|---|---|---|
| Haiku 5.5 low | あり（納豆パックを3回とも落とした） | 9.6% / 13.4% | 2.9秒 | 約0.1円 |
| Sonnet 5.5 medium | なし | 6.6% / 10.1% | 4.3秒 | 約1.9円 |
| Opus 5.5 medium | なし | 3.5% / 9.1% | 7.4秒 | 約4.2円 |

## 決定

1. 写真からの推定のモデルは **`claude-sonnet-5-5`、effort は `medium`** とする
2. 画像は OCR と同じく長辺 1024px 程度に縮小して送る（ADR-0010。写真推定でのサイズ比較はしていない）
3. 推定結果を保存するときは、モデルID・`prompt_version`・スキーマのバージョンを一緒に記録する（LLM-07）

## 理由

- 品目が抜けるとその分がまるごと記録されない。正解がなくても分かる欠点で、Haiku にはそれがあった
- Sonnet は再現性の目安（CV 10% 以内）をほぼ満たし（5枚中4枚、最大 10.1%）、応答も目安の 5秒以内
- Opus は最も安定しているが、応答が 7秒台で費用は約2倍。精度を測れない以上、その差に見合うか判断できない
- 費用は 1日3回で月約170円。月1000円（NFR-001）に収まる（自分専用の場合）

## 影響

- 入力方式によってモデルが違う（OCR は Haiku 5.5、写真推定は Sonnet 5.5）。バックエンドでは用途ごとにモデルIDを設定で持つ
- 推定値は目安値として登録する。確認画面で料理名・分量を直せるようにする（Q-28）
- プロンプトの改善（料理単位で分ける、パック食品も品目に入れる）は別途行い、Sonnet で効果を確かめる
- ストア公開で利用者が増えたら費用を見直す（Haiku＋プロンプト改善の再検証、回数制限 LLM-10 など）
