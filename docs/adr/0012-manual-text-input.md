# ADR-0012: 入力方式④は「食品名と数値の手入力」とし、Claude は使わない

- ステータス: Accepted
- 日付: 2026-11-13
- 関連: Q-19, Q-30, REQ-04, LLM-01, LLM-03, IMP-03

## 背景

Q-19 で「テキスト入力を MVP に含める」と決めたが、これを「料理の説明文から Claude が推定する（テキスト推定）」と解釈し、`contracts/llm/text-estimate/` の契約と PoC-4 の計画を作っていた。2026-11-13、ユーザーから「テキスト推定ではなく、ユーザーによるテキスト入力が正しい。画像・バーコード・OCR で推定できない、または精度が悪いときに使う想定」と訂正があった。

## 決定

1. 入力方式④は**利用者が食品名と数値（kcal・P・F・C）を手で入力し、そのまま登録する**方式とする
2. Claude は使わない。`contracts/llm/text-estimate/` は削除し（コミット `e6612c4` までの Git 履歴に残る）、PoC-4 は SKIP にする
3. 位置づけは**最後の手段**。バーコード・OCR・写真推定で推定できないとき、または結果が不正確なときに使う（基本方針「キーボード入力は最終手段」と同じ）

## 理由

- 他の3方式が使えない・合わないときに、確実に正しい値を残せる手段が必要。そこで再び推定させると、精度が悪いという問題が解決しない
- Claude を呼ばないので、費用・応答時間・契約とテストの管理が増えない

## 影響

- 入力した値は「食べた量の値」としてそのまま登録する。分量のワンタップ選択や、値の基準（100g 当たりなど）の換算は行わない
- 入力項目のどれを必須にするか（例: kcal だけ必須で PFC は任意か）、他の方式の失敗画面から手入力へ移る導線は、画面設計（UIX）で決める
- データモデル（DAT-01, DAT-04）: 値の出どころの種類は「Open Food Facts / OCR / 写真推定 / 手入力」になる（ADR-0009 の「テキスト推定」を置き換える）
- 料理名から値を補う機能（日本食品標準成分表での検索など）は将来の拡張（EXT-05）として残す
