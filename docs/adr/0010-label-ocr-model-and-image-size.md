# ADR-0010: 栄養成分表示 OCR は Haiku 5.5（effort low）で、画像は長辺 1024〜1568px に縮小して送る

- ステータス: Accepted
- 日付: 2026-11-13
- 関連: Q-24, POC-23, POC-41, POC-42, POC-43, LLM-07, [PoC-2 結果](../../poc/reports/poc2-label-ocr.md)

## 背景

PoC-2 で、Haiku / Sonnet / Opus 5.5 に栄養成分表示の写真4枚（条件のよい2枚、逆光1枚、袋の曲面・斜め・小さい文字1枚）を読ませた。

- 読める3枚: 全モデル・全 effort で kcal・P・F・C が正確
- 読めない1枚: 全モデルが `unreadable` を返し、値を推測で埋めなかった（上位モデルでも読めない）。正面から撮り直すと Haiku 5.5 で正確
- 1回の費用: Haiku 約0.1円 / Sonnet 約2円 / Opus 約4円
- 画像の縮小: 長辺 1024px は元サイズと同じ結果、768px では1か所誤読

## 決定

1. 栄養成分表示 OCR のモデルは **`claude-haiku-5-5`、effort は `low`** とする
2. 画像は端末側で**長辺 1024〜1568px に縮小**し、JPEG にして送る（768px 以下にはしない）
3. 推定結果を保存するときは、モデルID・`prompt_version`・スキーマのバージョンを一緒に記録する（LLM-07）

## 理由

- 精度の差が出なかった。厳しい条件でも、読める写真は全モデルが正確で、読めない写真は全モデルが読めなかった
- 費用は Sonnet の約20分の1、Opus の約40分の1。月1000円の上限（NFR-001）に対して十分な余裕がある
- 長辺 1024px は元サイズと同じ精度で、入力トークンが約2割少なく、Lambda の 6MB 上限にも十分収まる（約200KB）

## 影響

- 読めない写真の対策はモデルの変更ではなく、撮り直しの案内で行う（Q-25、[scope.md](../01_requirements/scope.md)）
- 写真4枚での判断のため、実際に使いながら読み違い・読めない例を記録し、増えたら Sonnet 5.5 などと再比較する
- 写真推定（PoC-3）のモデルは別途決める（→ ADR-0011。テキスト推定は ADR-0012 で廃止）
- プロンプトキャッシュの効果（POC-44）は未検証。Haiku では費用がもともと小さいので優先度は低い
