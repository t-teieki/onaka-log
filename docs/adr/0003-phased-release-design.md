# ADR-0003: 「自分専用 → 将来ストア公開」を前提に設計する

- ステータス: Accepted
- 日付: 2026-11-11
- 関連: Q-01, REQ-01, LLM-02, AUT-01, DAT-01, SEC-01

## 背景

直近の利用者は開発者本人のみ。ただし将来は iOS/Android ストアでの一般公開を視野に入れている。自分専用に最適化すると、公開時に認証・キー管理・データ構造の作り直しが発生する。

## 決定

自分専用の段階から、**公開時に作り直しが必要になる部分だけは最初から公開仕様で作る**。

| 領域 | 最初から公開仕様で作る | 公開時まで後回しにしてよい |
|---|---|---|
| Claude API キー | **アプリに持たせない。バックエンド経由で呼ぶ**（LLM-02 決定） | — |
| データモデル | 全データに `user_id`、マルチユーザー前提 | — |
| 認証 | 仕組みは最初から入れる方向（方式は Q-17 で確定） | ソーシャルログインの種類追加 |
| 不正利用対策 | ユーザーごとの回数制限 | App Attest / Play Integrity |
| 法務 | 外部送信するデータの洗い出し | 利用規約・プライバシーポリシー・ストア審査対応 |
| 対象 OS | iOS・Android 両対応のクロスプラットフォーム | Android 実機での検証（エミュレータで代替） |

## 理由と影響

- キーをアプリに埋め込むと、公開時にキーを抜かれるリスクがある。後から経路を変えると API 契約ごと変わるため、最初からバックエンド経由にする。
- バックエンドが必須になるため、運用コスト（月1000円以内、NFR-001）の中で無料枠に収まる構成を選ぶ必要がある（Q-12）。
