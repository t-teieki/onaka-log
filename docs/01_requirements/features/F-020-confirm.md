# F-020 確認・修正の画面

> ステータス: Draft
> 最終更新: 2026-11-16
> 関連: [screens](../../02_design/screens/README.md) §3-5, [domain-model.md](../../02_design/domain-model.md) §2-3, [ADR-0009](../../adr/0009-barcode-adoption-and-net-content.md), [ADR-0015](../../adr/0015-server-first-and-sync-estimation.md), Q-14, Q-27, Q-31, Q-33

推定・照合 API が返した候補（`FoodItemDraft`）を表示し、名前と分量を決めて保存する。手入力は同じ画面の入力モード（F-014、[ADR-0012](../../adr/0012-manual-text-input.md)）。

## 要件（アプリ側）

| ID | 要件 |
|---|---|
| F-020-01 | 候補ごとに食品カードを出す。食品名（タップで修正。空のときは保存できない、100文字まで）、出どころ（「Open Food Facts」など）、基準と内容量（「100g当たり・内容量 78g」「100g当たり・内容量：不明」など） |
| F-020-02 | 分量のボタンを出す。基準が `per_piece` なら「1個」「2個」「3個」（内容量の個数が分かれば「全部」も）、それ以外は「全部」「3/4」「1/2」「1/4」。既定は候補の `default_portion` |
| F-020-03 | 選んだ分量での値をプレビューする（domain-model §2-3 の倍率、DM-03 と同じく小数第1位で四捨五入。kcal は整数で表示、不明は「—」）。画面の下に合計（kcal）と、不明を含めば「一部不明」 |
| F-020-04 | 食べた日時は手入力と同じ（既定・ピッカー・今まで、Q-33・Q-44）。追加モードでは出さない |
| F-020-05 | 保存は、新しい記録なら `POST /v1/meals`、追加モードなら `POST …/meals/{meal_id}/items`（F-030-10〜12 と同じ扱い）。送る食品は候補の `source`・`reference`・`estimate_detail` をそのまま、名前と分量（`mode`・`fraction`・`pieces`）を画面で選んだもの。食事・食品の ID は画面を開いたときに決める。保存のボタンは追加モードでは「食事に追加」。追加モードで食品が2件以上（写真推定）なら、1件ずつ順に送る（2件目からは前の応答の版を使う。途中で失敗して押し直しても、送り済みの食品は `item_already_exists` で成功として扱うので二重にならない） |
| F-020-06 | バーコードの候補のときは「栄養成分表示を撮る」を出す（登録ミス対策、ADR-0009）。押すと撮影の画面へ（F-012-15。記録日と追加先を引き継ぐ） |
| F-020-07 | 栄養成分表示の候補が2件以上（複数列）なら、1枚のカードの上の方に列のボタン（見出し、なければ「1列目」「2列目」）を出し、先頭の列を選んだ状態で開く。列を変えると、名前・基準・値・分量をその列の候補に合わせる（Q-26・Q-37） |
| F-020-08 | 写真推定の候補なら、画面の上部に「写真からの推定（目安）です」を出し、品目ごとにカードを出す。信頼度（`source.confidence`）が `low` の品目には「目安」の印を付ける。品目は × で外せ、0件になったら保存できない（Q-28） |
