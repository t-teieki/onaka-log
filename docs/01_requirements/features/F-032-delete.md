# F-032 食事・食品の削除

> ステータス: Draft
> 最終更新: 2026-11-16
> 関連: [api.md](../../02_design/api.md), [screens](../../02_design/screens/README.md) §3-9, Q-31, Q-39
> API: `DELETE /v1/days/{record_date}/meals/{meal_id}`、`DELETE /v1/days/{record_date}/meals/{meal_id}/items/{item_id}?expected_version=`

「元に戻す」（Q-39）はアプリが削除 API を送るのを遅らせて実現するので、API に取り消しはない。

## API 側の要件

| ID | 要件 |
|---|---|
| F-032-01 | 食事の削除は 204。なければ 404 not_found。物理削除（ADR-0013） |
| F-032-02 | 食品の削除は、消した後の食事を 200 で返す（`meal_deleted: false`、`version` +1、合計を計算し直す） |
| F-032-03 | 最後の1件の食品を消したら食事ごと削除し、`meal_deleted: true`、`meal: null` を 200 で返す（Q-31） |
| F-032-04 | 食事がない、または食品がなければ 404 not_found。`expected_version` が今の版と違えば 409 version_conflict |
| F-032-05 | ほかの利用者の食事は消せない（404 not_found） |

## アプリ側: 削除と「元に戻す」（2026-11-16、画面設計 3-6・3-9）

| ID | 要件 |
|---|---|
| F-032-06 | 食事の詳細で、食品ごとの「削除」と「この食事を削除」を押すと、確認を出さずにすぐ表示から消し、画面の下に「削除しました［元に戻す］」を約5秒出す |
| F-032-07 | 「元に戻す」を押したら削除 API を送らず、表示を戻す |
| F-032-08 | 削除 API を送るのは、5秒たったとき・アプリがバックグラウンドに移ったとき・次の削除を始めたとき。「元に戻す」のバーはアプリ全体で1本で、画面を移ってもバーとタイマーは続く（画面を離れただけでは送らない） |
| F-032-09 | 削除を待っている間（送り終えるまで）は、ホームと詳細の両方で、消した食事・食品を出さず、合計もそれを除いて出す。送り終えたら、その日と食事を読み直す |
| F-032-10 | 最後の1件の食品を消したとき、または「この食事を削除」のときは、ホームに戻ってバーを出す。最後の食品は食品の削除 API で送る（サーバーが食事ごと消す、F-032-03） |
| F-032-11 | 食品の削除は、送る時点で手元にある最新の版を `expected_version` に付ける。削除は1件ずつ順に送り、前の応答の食事で版を更新してから次を送る |
| F-032-12 | 404 はもう消えているので成功と同じに扱う。409 なら「ほかの変更と重なったため削除できませんでした」、そのほかの失敗は「削除できませんでした」をバーに出し、読み直して表示を戻す |
