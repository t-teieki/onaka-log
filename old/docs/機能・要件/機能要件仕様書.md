# 食事記録アプリ 機能・要件仕様書

## 1. 概要
- **目的**: 食事内容とカロリー・PFCを手軽に記録し、日ごとに振り返る
- **利用形態**: 個人利用のみ・自環境で動かす最小構成(配布は想定しない)
- **関連資料**: フロー・アーキテクチャ(改訂版 v2)

## 2. 機能一覧

| ID | 機能 | 概要 |
|---|---|---|
| F-1 | 食事記録 | 4つの入力方法から選んで記録する |
| F-2 | 記録の閲覧 | 日付別に一覧と日次合計を見る |
| F-3 | 記録の編集 | 保存済みの記録を修正する |
| F-4 | 記録の削除 | 保存済みの記録を削除する |

## 3. 機能要件

### 3-1. 食事記録(F-1)

**入力方法**(記録開始時にユーザーが選択)

| 方式 | 内容 |
|---|---|
| A. バーコード照合 | バーコードをスキャンし、Open Food Factsで商品情報を取得 |
| B. 栄養成分表示OCR | 栄養成分表示を撮影し、Geminiで抽出・構造化 |
| C. 写真AI推定 | 料理を撮影し、Geminiで料理名・カロリー・PFCを推定 |
| D. 手動入力 | 食品名・カロリー・PFCを手入力 |

**記録項目**

| 項目 | 内容 |
|---|---|
| タイトル | 食品名・料理名 |
| カロリー | kcal |
| P・F・C | たんぱく質・脂質・炭水化物(g) |
| 記録日時 | 食べた日時。初期値は現在日時で、過去日時に変更できる |
| 食事区分 | 朝食/昼食/夕食/間食 |
| 記録元 | バーコード/OCR/写真/手動 |

**要件**
- F-1-1: 失敗時(未登録・読み取り不可・認識不可・通信エラー等)はエラーメッセージを表示し、入力方法の選択に戻る
- F-1-2: いずれの方式でも、保存前に確認画面でユーザーが値を修正できる。写真推定(C)は常に修正前提とする
- F-1-3: 取得した値はそのまま記録する(摂取量による補正は行わない。今後拡張予定)
- F-1-4: 記録日時は過去日時を指定できる
- F-1-5: 食事区分は記録日時から初期値を提示し、ユーザーが変更できる
- F-1-6: **写真は保持しない**。データ取得後、成功・失敗を問わず撮影画像を破棄する(端末内に残さない)
- F-1-7: 保存先は端末内のローカルDBとする

### 3-2. 記録の閲覧(F-2)
- F-2-1: 日付を指定して、その日の記録一覧を表示する(初期表示は今日)
- F-2-2: 一覧には各記録のタイトル、推定カロリー、P・F・C、食事区分、記録元を表示する
- F-2-3: 一覧の上部または下部に、その日の合計(カロリー・P・F・C)を表示する
- F-2-4: 記録元(バーコード/OCR/写真/手動)を区別して表示し、AI推定値と見分けられるようにする
- F-2-5: 食事区分ごとにグループ化して表示する
- F-2-6: 記録がない日は、その旨を表示する

### 3-3. 記録の編集(F-3)
- F-3-1: 一覧から記録を選択して編集できる
- F-3-2: 編集可能項目は、タイトル、カロリー、P・F・C、記録日時、食事区分とする
- F-3-3: 保存すると一覧と日次合計に反映される
- F-3-4: 記録元は編集後も元の値を保持する

### 3-4. 記録の削除(F-4)
- F-4-1: 一覧から記録を選択して削除できる
- F-4-2: 削除前に確認ダイアログを表示する
- F-4-3: 削除すると日次合計に反映される

## 4. 非機能要件

| 区分 | 内容 |
|---|---|
| データ保存 | 記録はすべて端末内のローカルDBに保存する |
| 外部通信 | バーコード番号をOpen Food Factsへ、撮影画像をGemini APIへ送信する。それ以外のデータは外部に送信しない |
| 画像の扱い | 撮影画像は取得完了後(成功・失敗とも)に破棄し、保存しない |
| ネットワーク | A・B・Cはネットワークが必要。閲覧・編集・削除・手動入力はオフラインでも利用できる。通信エラー時はエラーメッセージを表示するのみとし、オフライン専用の処理は設けない |
| 権限 | カメラ権限を使用する。拒否された場合はその旨を表示し、手動入力は利用できる |
| セキュリティ | APIキーは個人利用のため、クライアントでの直接保持を許容する。ただしGit管理には含めない |
| 配布 | 想定しない |

## 5. スコープ外(今回は対応しない)
- 履歴から再記録
- 目標値の設定と達成度表示
- 記録画像の保存・表示
- 摂取量(分量)の入力と再計算
- 週・月の推移グラフ
- 食品名・キーワード検索
- データのエクスポート・バックアップ
- 微量栄養素(塩分・食物繊維など)の記録
- オフライン専用処理(キャッシュ・同期)
- 配布対応(プロキシ・利用コスト・プライバシー)

## 6. 未決事項
1. **日付の切り替わり**: 1日の境界を0:00とするか(深夜の食事の扱い)
2. **食事区分の初期値ルール**: 時間帯と区分の対応(例: 5〜10時=朝食)
3. **日付の移動UI**: 前日・翌日ボタン、カレンダー選択のどちらにするか
4. **カロリー・PFCの入力制約**: 必須か任意か、小数を許容するか
5. **同一商品の重複記録**: 同じ商品を何度記録しても許容するか(現状は許容を想定)
